# Migration Generation

Aggo can generate `CREATE TABLE` DDL directly from your `Table` descriptors.
Column types are inferred from each column's `Codec`, CHECK constraints come from
the `check = …` parameters you already declared, and the PRIMARY KEY clause is
built from columns with `isPrimaryKey = true`.

## createTableSql

```kotlin
import com.aggitech.aggo.dialect.PostgresDialect
import com.aggitech.aggo.migration.createTableSql

println(UsersTable.createTableSql(PostgresDialect))
```

Output:

```sql
CREATE TABLE "users" (
    "id" TEXT NOT NULL,
    "email" TEXT NOT NULL,
    "name" TEXT NOT NULL,
    "active" BOOLEAN NOT NULL,
    "created_at" TIMESTAMPTZ NOT NULL,
    CONSTRAINT chk_users_email CHECK ("email" ~ '^[^@\s]+@[^@\s]+\.[^@\s]+$' AND char_length("email") <= 255),
    CONSTRAINT chk_users_name CHECK (trim("name") <> ''),
    PRIMARY KEY ("id")
);
```

### IF NOT EXISTS

```kotlin
println(UsersTable.createTableSql(PostgresDialect, ifNotExists = true))
// CREATE TABLE IF NOT EXISTS "users" ( ...
```

### Nullable columns

Columns declared with `isNullable = true` emit no `NOT NULL` clause:

```kotlin
val deletedAt = column("deleted_at", InstantCodec, isNullable = true) { it.deletedAt }
// → "deleted_at" TIMESTAMPTZ
```

### Generated columns

Columns with `isGenerated = true` appear in the DDL with their type but **without**
a DEFAULT or GENERATED expression — the framework cannot infer the database-side
generation strategy. Add the expression manually in your migration script:

```sql
-- Generated by Aggo:
"id" INTEGER NOT NULL,
-- Add manually:
"id" INTEGER NOT NULL GENERATED ALWAYS AS IDENTITY,
-- or:
"id" UUID NOT NULL DEFAULT gen_random_uuid(),
```

## dropTableSql

```kotlin
import com.aggitech.aggo.migration.dropTableSql

println(UsersTable.dropTableSql(PostgresDialect))
// DROP TABLE "users";

println(UsersTable.dropTableSql(PostgresDialect, ifExists = true))
// DROP TABLE IF EXISTS "users";
```

## Generating ALTER TABLE for existing tables

If the table already exists and you need to add CHECK constraints:

```kotlin
// Returns a list of ALTER TABLE … ADD CONSTRAINT … statements
UsersTable.addCheckConstraintsSql().forEach(::println)
```

Output:

```sql
ALTER TABLE "users" ADD CONSTRAINT chk_users_email CHECK ("email" ~ '^[^@\s]+@[^@\s]+\.[^@\s]+$' AND char_length("email") <= 255);
ALTER TABLE "users" ADD CONSTRAINT chk_users_name CHECK (trim("name") <> '');
```

## Inline CHECK clauses only

If you are writing your own CREATE TABLE statement and want to embed the constraints:

```kotlin
UsersTable.checkConstraintClauses().forEach(::println)
// CONSTRAINT chk_users_email CHECK (...)
// CONSTRAINT chk_users_name CHECK (...)
```

## Generating migrations for all tables at startup (script)

```kotlin
fun main() {
    val tables = listOf(UsersTable, OrdersTable, ProductsTable, InvoicesTable)

    tables.forEach { table ->
        println("-- ${table.name}")
        println(table.createTableSql(PostgresDialect, ifNotExists = true))
        println()
    }
}
```

```xml
            "created_at" TIMESTAMPTZ NOT NULL DEFAULT now(),
            CONSTRAINT chk_users_email CHECK (...),
            CONSTRAINT chk_users_name CHECK (...),
            PRIMARY KEY ("id")
        );
    </sql>
    <rollback>DROP TABLE "users";</rollback>
</changeSet>
```

## SQL type mapping reference

| Codec | PostgreSQL column type |
|-------|------------------------|
| `StringCodec` / `ValueClassCodec(StringCodec, …)` | `TEXT` |
| `IntCodec` | `INTEGER` |
| `LongCodec` | `BIGINT` |
| `ShortCodec` | `SMALLINT` |
| `DoubleCodec` | `DOUBLE PRECISION` |
| `BooleanCodec` | `BOOLEAN` |
| `BigDecimalCodec` | `NUMERIC` |
| `InstantCodec` | `TIMESTAMPTZ` |
| `LocalDateTimeCodec` | `TIMESTAMP` |
| `LocalDateCodec` | `DATE` |
| `UuidCodec` | `UUID` |
| `TsidCodec` | `TEXT` |
| `UlidCodec` | `TEXT` |
| `ValueClassCodec(XCodec, …)` | same as `XCodec` |

`ValueClassCodec` automatically delegates to the underlying raw codec's SQL type,
so custom domain types (e.g. `EmailCodec = ValueClassCodec(StringCodec, …)`) resolve
to `TEXT` without any extra configuration.

## Supporting other databases

Implement `MigrationDialect` for a different database engine:

```kotlin
import com.aggitech.aggo.dialect.MigrationDialect
import com.aggitech.aggo.schema.Codec
import java.math.BigDecimal
import java.time.LocalDate
import java.time.LocalDateTime
import java.time.OffsetDateTime
import java.util.UUID

object MySqlDialect : MigrationDialect {
    override fun placeholder(oneBasedIndex: Int) = "?"
    override fun quoteIdentifier(name: String): String {
        requireValidIdentifier(name)
        return "`$name`"
    }
    override fun columnSqlType(codec: Codec<*>) = when (codec.sqlType) {
        String::class.java              -> "TEXT"
        Int::class.javaObjectType       -> "INT"
        Long::class.javaObjectType      -> "BIGINT"
        Boolean::class.javaObjectType   -> "TINYINT(1)"
        BigDecimal::class.java          -> "DECIMAL(19,4)"
        OffsetDateTime::class.java      -> "DATETIME(6)"
        LocalDateTime::class.java       -> "DATETIME"
        LocalDate::class.java           -> "DATE"
        UUID::class.java                -> "CHAR(36)"
        else -> throw UnsupportedOperationException("No MySQL type for ${codec.sqlType.name}")
    }
}

println(UsersTable.createTableSql(MySqlDialect))
```
